## Detailed findings

### Layer 1 — Universe + Watchlist Categorization

#### ✅ FIX 1.1: MOMENTUM swing re-enabled

**Bug:**
- `universe_service.py:4824-4835` had a comment claiming MOMENTUM "uses bar-count timing logic that's intraday-calibrated" and intentionally excluded it from `_long_candidates` (swing watchlist emission).
- `trading_service.py:874-883` had MOMENTUM in `_intraday_only_strategies`, silently retagging any swing-tagged MOMENTUM row to intraday.

**Reality:**
- `check_swing_entry()` for MOMENTUM at `scoring.py:804-838` uses ALL daily-frame indicators: trend, ema_stack, supertrend_dir, ADX, strength, RSI. Setup IS daily-calibrated.
- Universe ALREADY computes MOMENTUM score on daily candles (`universe_service.py:4769-4786`) with sound formula:
  `0.50 × RS(60d) + 0.20 × trend + 0.15 × ADX + 0.10 × persistence + 0.05 × volume`.
- This is the canonical relative-strength momentum strategy validated by IBD CANSLIM, AQR, Druckenmiller, etc.

**Production impact:** 0 MOMENTUM swing scans in 13 days (5/12 → 5/25). The setup that's most-likely to make money in trending markets is invisible.

**Fix applied:**
1. `universe_service.py:4841`: Added `("MOMENTUM", "BUY", momentum)` to `_long_candidates`.
2. `trading_service.py:881`: Removed `"MOMENTUM"` from `_intraday_only_strategies`.
3. `tests/test_swing_multi_emission.py`: Updated assertion list — MOMENTUM moved from "must_stay" to "must_not_be_present". Test now correctly enforces the new design.

**Validation:**
- 85 affected tests pass (`test_swing_multi_emission`, `test_swing_momentum`, `test_universe_v2`, `test_strategy_audit_fixes_2026_05_08`, `test_m2_playbook_edge`).
- Python imports clean; no syntax regressions.

**Expected impact:** Reactivates a setup that previously fired 339 trades in 2yr backtest. Real production should see MOMENTUM swing scans appear in scan_decisions after deploy.

#### 📝 Finding 1.2: PULLBACK emission rate is low

### Layer 3 — Hard-Blocks (`regime_affinity._HARD_BLOCKS`)

#### ❌ Investigated, NOT shipped: BREAKOUT in TREND_UP

**Initial attempt:** Removed BREAKOUT from TREND_UP hard-block list.

**Result:** Failed `test_breakout_still_hard_blocked_in_trend_regimes` which is a regression guard stating "future re-enable requires VCP/cup-handle pattern detection."

**Decision:** Reverted. The test author was correct — current `check_swing_entry()` gates check trend strength (ADX, EMA, volume) but DO NOT verify the stock is breaking out of a tight consolidation base (VCP, cup-and-handle, multi-week structure). Without these structural pattern detectors, BREAKOUT in TREND_UP would fire on any uptrending stock with high ADX, which is generic momentum (already covered by MOMENTUM setup).

**Recommendation:** Build a pattern-detection module that identifies tight consolidation bases (VCP / cup-handle / IBD pivot points) before re-enabling BREAKOUT. Add as a new daily_bias attribute (e.g., `daily_bias.base_pattern_quality`). Then unblock BREAKOUT in TREND_UP conditional on `base_pattern_quality >= 70`.

### Layer 4 — Position Sizing + Risk

#### 📝 No change: ratios are within acceptable range

- Intraday `atr_sl_mult = 1.5` + 0.8% floor.
- Swing `atr_sl_mult = 2.5` + 1.0% floor.
- Intraday `rr = 1.25`, swing `rr = 2.0`, MR `rr = 2.0`.

**Real data analysis** confirmed the system has a math problem:
- TARGET_HIT: 5/95 = 5.3% (need ~44% for positive expectancy at 1.25 RR)
- SL_HIT: 30/95 = 31.6%
- This is a SCORING-quality problem, not a sizing problem.

**Recommendation:** Don't loosen SL further (would make individual losses worse). Instead, improve signal quality through MOMENTUM swing re-enable and pattern-detection.
